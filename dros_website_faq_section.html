常見問題與技術優勢 (FAQ)

「開放身份，在地治理 (Open Identity, Localized Governance)」── 對齊 IEEE 論文 6-Pillars 與 U.S. Patent 64/111,973 標準。

Q1. 什麼是「開放身份，在地治理 (Open Identity, Localized Governance)」？外部 Agent 持護照來訪會威脅企業嗎？
RFC-010 開放護照 + 在地 GuardVM 門禁

完全不會！這正是 DROS 解決 Agentic Web 信任衝突的核心範式。

外部 Agent 攜帶 RFC-010 護照 (libdros-id) 來訪時，僅提供其身分歸因 (Principal) 與發行簽章。企業在地的 GuardVM 網關保有 100% 的確定性執行裁量權：

企業在 VajraAgent 主控頁 上，可以直接為該外部護照設定在地 Capability Bitmaps (位元圖矩陣)。即使外部護照聲稱自己具備超級管理員權限，DROS 在 C-ABI 帶內層級 (26.1μs) 依然僅允許其調用企業開通的特定 API。任何越權呼叫直接物理熔斷並返回 HTTP 403。
Q2. 企業如何透過 VajraAgent 主控頁進行「對內」與「對外」的雙向權限區隔與操作？
雙向權限總控台 (Dual-Direction Control)

VajraAgent 提供極致直觀的雙向治理控制台：

  • 對外 API 門禁治理：視覺化勾選與調整 Capability 位元圖矩陣，即時設定外部 Agent 的存取 Scope 與 PII 遮蔽門閥。
  • 對內 Agent 護照簽發：一鍵為企業內部的 AI 員工簽發 3-Tier PKI DIT 護照 (BEC 憑證)，設定該 Agent 出門後的存取邊界與可攜帶資料標籤。
  • 一鍵 RCU 即時黑名單：當發現異常 Agent，點擊撤銷按鈕，<1μs 內以 RCU 原子指針切換將該 Agent 全網封鎖。
Q3. DROS 提出的「6-Pillars 確定性治理」與傳統的 IAM / OAuth 或 API Gateway 有何本質區別？
物理層 C-ABI 帶內硬熔斷 vs. 網路層軟邊界

傳統 API Gateway 運作在 Out-of-band HTTP 網路層 (延遲高達 4ms~50ms)，無法防禦二進位 FFI 越權，且 IAM 僅能提供粗粒度的使用者級 Scope。DROS-6P 則在物理層 C-ABI / eBPF 直接運作：

  • 超低延遲：平均決策延遲僅 26.1 μs (p99 = 29.8 μs)，效能提升數千倍。
  • 密碼學證明：內建 SHA-256 Merkle 雜湊稽核鏈與 Ed25519 簽章，產出不可否認性的法務級憑證。
Q4. 攻擊者若利用 Prompt Injection 誘騙 Agent 輸出客戶個資，DROS 如何防禦？
Pillar 4 Policy Gate + PII 動態遮蔽

DROS 部署了帶內物理層的 Policy Gate：

當 Agent 試圖調用敏感資料時，Policy Gate 會在二進位層級自動進行欄位動態遮蔽 (PII Redaction)；若涉及高風險資金轉帳或全域刪除，自動觸發 HITL (Human-In-The-Loop) 懸停等待人類雙簽核可，完全封殺語意越權。井然有序，滴水不漏。

Q5. 企業部署 DROS 需要修改原有的 AI Agent 程式碼 (如 LangChain / AutoGen) 嗎？
零程式碼修改 ‧ 零系統停機

完全不需要！DROS 採用外部 C-ABI / eBPF 帶內攔截與開箱即用的 `libdros-id` SDK：

管理者透過宣告式策略合約 (vajra.yaml) 或 VajraAgent Web 主控台調整權限後，DROS 控制平面便會在微秒內完成熱加載 (Hot Reloading)，AI 員工運作零中斷，為企業提供高防衛、零負擔的防禦經驗。
